# کیس‌استادی ITXN v2.2 — سه روش + مسیر مدل رایگان

این پروژه سه روش را روی همان دیتاست مصنوعی ITXN مقایسه می‌کند:

1. `baseline.py`: محاسبات و قواعد قطعی پایتون، بدون LLM.
2. `agent.py`: ایجنت ابزارمحور؛ اجرای واقعی مدل فقط در حالت اختیاری `live` انجام می‌شود. حالت `offline` شبیه‌سازی صریح است.
3. `agent_harness.py`: همان ایجنت به‌علاوه کنترل قرارداد خروجی، شواهد، نتیجه مجاز و رد خروجی نامعتبر.

## اجرای رایگان و بدون درخواست مدل

با Python 3.10 یا بالاتر:

```bash
python run_demo.py
python -m unittest discover -s tests -v
```

این اجرا هیچ API یا مدلی را صدا نمی‌زند و نتایج را در `reports/` می‌نویسد. خروجی‌های Agent در این حالت شبیه‌سازی هستند؛ بنابراین از آن‌ها نمی‌توان کیفیت استدلال یک LLM واقعی یا سرعت و هزینه اجرای مدل را نتیجه گرفت.

## اجرای راحت‌تر با موبایل در Codespaces

اگر فقط با گوشی کار می‌کنی، لازم نیست در Settings، Secret بسازی. بعد از اینکه فایل ZIP را در ریشه مخزن GitHub آپلود و Commit کردی، در ترمینال Codespaces این فرمان را اجرا کن:

```bash
mkdir -p itxn-run && unzip -oq itxn_credit_three_way_v2_2_mobile.zip -d itxn-run && cd itxn-run/itxn_credit_three_way_v2_2 && bash mobile_start.sh
```

اسکریپت کلید OpenRouter را در ترمینال به‌صورت مخفی می‌پرسد؛ کلید در فایل یا مخزن ذخیره نمی‌شود. فقط یک مشتری مصنوعی را بررسی می‌کند و حداکثر دو درخواست می‌فرستد. اگر نمی‌خواهی هنوز درخواست مدل مصرف شود، کلید را وارد نکن و اجرا را متوقف کن. پس از پایان، گزارش در `reports/live_comparison_SYN-CUST-0001.json` قرار می‌گیرد. فایل ZIP را از ریشه مخزن آپلود کن تا نام آن دقیقاً `itxn_credit_three_way_v2_2_mobile.zip` باشد.

## اجرای اختیاری مدل واقعی روی فقط یک مشتری

این مرحله خودکار اجرا نمی‌شود و ممکن است هزینه ارائه‌دهنده مدل داشته باشد. برای کاهش هزینه، شناسه مشتری اجباری است، هر اجرا حداکثر دو درخواست مدل می‌فرستد و retry خودکار ندارد:

```bash
export LLM_BASE_URL="https://openrouter.ai/api/v1"
export LLM_API_KEY="کلید ارائه‌دهنده خودت"
export LLM_MODEL="شناسه مدلی که tool calling پشتیبانی می‌کند"
python agent.py --mode live --customer SYN-CUST-0001
python agent_harness.py --mode live --customer SYN-CUST-0001
```

کلید را داخل کد یا مخزن Git قرار نده. دسترسی به ChatGPT لزوماً به معنی اعتبار API رایگان نیست. برای این مرحله عجله نکن؛ اول خروجی رایگان را مرور کن.

## آنچه فعلاً تأیید شده

- ۲۵۰۴ ردیف تراکنش مصنوعی، ۸۰ مشتری مصنوعی و ۱۷ ستون.
- ۵۷ ردیف با `rev_flag=1`؛ در ۳۳ مشتری دست‌کم یک چنین ردیفی وجود دارد.
- آزمون‌های خودکار نسخه اولیه ۱۰ مورد بودند؛ نسخه ۲.۲ اکنون ۲۲ آزمون دارد و نتیجه کامل در `VERIFICATION_v2.2.txt` آمده است.
- ۸۰ از ۸۰ گزارش شبیه‌سازی‌شده، کنترل‌های عادی Harness را گذرانده‌اند.
- هیچ‌یک از سه برنامه تأیید یا رد اعتبار صادر نمی‌کند؛ خروجی همه `HUMAN_REVIEW_REQUIRED` است.

**محدودیت مهم:** این کیس‌استادی فعالیت تراکنشی را توصیف می‌کند، نه توان بازپرداخت را. معنای `respcode == "00"` نیز در این پروژه صرفاً قرارداد داده مصنوعی است و باید پیش از استفاده از داده واقعی با تعریف رسمی فیلد تطبیق داده شود.

## ارزیابی کنترل‌شده کم‌هزینه (v2.1؛ در بسته v2.2 نیز حفظ شده است)

برای بررسی تفاوت واقعیِ قابل سنجش، فرمان زیر را اجرا کنید:

```bash
python run_controlled_evaluation.py
```

این مرحله مدل زبانی را صدا نمی‌زند و هیچ اعتبار API مصرف نمی‌کند. یک مثال مشخص از داده فعلی را به روش معمولی و Agent آفلاین می‌دهد، سپس چند خطای کنترل‌شده را در مرز خروجی Agent تزریق می‌کند تا مشخص شود Harness آن‌ها را رد می‌کند یا نه. این تزریق‌ها نشان نمی‌دهند که مدل زبانی واقعی حتماً چنین خطاهایی تولید می‌کند.

نسخه 2.1 کنترل‌های Harness را سخت‌تر می‌کند: خروجی باید دقیقاً کلیدهای قرارداد را داشته باشد، همه سیگنال‌های مشاهده‌شده را گزارش کند، نوع فهرست‌ها معتبر باشد و هیچ نتیجه اعتباری پشتیبانی‌نشده‌ای بیان نشود.

گزارش در `reports/controlled_evaluation.json` ذخیره می‌شود. تفسیر درست فعلی این است: محاسبات ویژگی‌ها میان روش‌ها مشترک و یکسان است؛ این اجرا هیچ برتریِ اعتبارسنجی اعتباری را نشان نمی‌دهد؛ آزمون‌های تزریق خطا فقط توان Harness در رد همان خطاهای طراحی‌شده را می‌سنجند. فهم درخواست به زبان طبیعی با مدل واقعی و پیش‌بینی بازپرداخت همچنان ارزیابی نشده‌اند.


## اجرای یک آزمایش واقعی با مدل رایگان (کم‌هزینه)

در حالت فعلی، `offline` فقط شبیه‌سازی است. برای یک آزمایش زنده و واقعی می‌توان از مسیر رایگان OpenRouter استفاده کرد: مدل را `openrouter/free` تنظیم می‌کنیم تا سرویس، از میان مدل‌های رایگانِ سازگار با tool calling و خروجی ساختاریافته انتخاب کند. موجود بودن مدل و محدودیت نرخ درخواست ممکن است تغییر کند؛ رایگان بودن به معنی تضمین دسترس‌پذیری همیشگی نیست. مستندات جاری: https://openrouter.ai/collections/free-models و https://openrouter.ai/docs/guides/routing/routers/free-router.

**اشتراک رایگان ChatGPT به‌تنهایی کلید API برنامه‌نویسی در اختیار کد قرار نمی‌دهد.** اجرای زنده به کلید OpenRouter یا یک ارائه‌دهنده سازگار نیاز دارد. OpenRouter رایگان نیز سرویس جداگانه‌ای است؛ ممکن است ثبت‌نام و کلید خودش را لازم داشته باشد.

تنظیم متغیرها در محیط اجرا (کلید را در چت نفرستید و داخل Git commit نکنید):

```bash
export OPENROUTER_API_KEY="کلید شخصی خودت"
export LLM_BASE_URL="https://openrouter.ai/api/v1"
export LLM_MODEL="openrouter/free"
python run_live_comparison.py --customer SYN-CUST-0001
```

فرمان آخر فقط **یک مشتری مصنوعی** را تحلیل می‌کند. ایجنت حداکثر دو درخواست مدل ارسال می‌کند: اول فراخوانی ابزار خواندنی، سپس خلاصه شواهد. همان پاسخ مدل بدون فراخوانی دوباره برای کنترل Harness استفاده می‌شود؛ بنابراین مقایسه منصفانه‌تر است و مصرف درخواست نصف می‌شود. retry خودکار وجود ندارد. گزارش در `reports/live_comparison_SYN-CUST-0001.json` ذخیره خواهد شد و نام مدل/مدل‌های واقعی گزارش‌شده از سوی ارائه‌دهنده و تعداد توکن‌ها را ثبت می‌کند، اگر API آن‌ها را برگرداند.

OpenRouter ممکن است در دو درخواست، دو مدل متفاوت از مسیر رایگان انتخاب کند؛ گزارش این را ثبت می‌کند. برای یک آزمایش کوچک، هدف فقط بررسی کارکرد واقعی tool calling و کنترل هارنس است، نه نتیجه‌گیری آماری درباره برتری کلی مدل‌ها. اگر بخواهیم مدل‌های مختلف را علمی مقایسه کنیم، بعداً مدل مشخص و ثابت را pin می‌کنیم.

**مهم:** فقط از `synthetic_itxn.csv` مصنوعی استفاده کنید. داده واقعی بانک، PAN، شناسه مشتری، یا هر داده حساس را به یک API خارجی ارسال نکنید. این آزمایش، اعتبارسنجی فعالیت تراکنشی است نه مدل پیش‌بینی بازپرداخت.
